# App Store のスクリーンショット

Mac App Store の製品ページに載せるスクリーンショット（日本語・英語 各 5 枚）の版下と、
書き出しの道具。

```bash
make screenshots
# または
marketing/screenshots/render.sh                      # 全部
marketing/screenshots/render.sh 02-auto-ducking ja   # 1 枚だけ
```

`marketing/screenshots/build/<ja|en>/*.png` に 2880×1800（16:10、アルファ無し）で出る。
ファイル名の番号順が App Store での並び順。

## 構成と狙い

買う前に試せない（体験版が無い）ため、スクリーンショットだけで「何ができて、
自分の困りごとが消えるのか」が分かることを目標にしている。1 枚 1 メッセージ。

| # | ファイル | 伝えること |
|---|---|---|
| 1 | `01-per-app-volume` | 何のアプリか。動画 30%・音楽 80%・通知ミュートという具体的な使い方 |
| 2 | `02-auto-ducking` | 通話が始まると他の音が自動で下がる |
| 3 | `03-per-device-memory` | イヤホンとスピーカーで別々の音量を覚える（2 つの状態を並べる） |
| 4 | `04-per-app-output` | アプリごとに出力先を選べる（出力先メニューを開いた状態） |
| 5 | `05-features` | 機能一覧と、買い切り・データ収集なし・録音送信なし・動作要件 |

一覧の 1 枚目は検索結果や製品ページの最初に出るため、ここだけで用途が伝わるように
している。

背景は Mac のデスクトップにして、その場面で音を出しているアプリのウインドウ
（動画を流しているブラウザ、ミュージックのミニプレーヤー、FaceTime の通話）を
ポップオーバーの下に置く。「いつ、何のために使うのか」を絵で分かるようにするため。
壁紙・動画・曲・通話相手はすべて架空のもので、macOS の壁紙は使っていない。

## 画面はアプリと同じ見た目で組んでいる

アプリ本体の画面は HTML で再現している（実機の画面を毎回撮り直さなくて済むように、
また「音量を変えた状態」を確実に作れるように）。**見た目も数値も実際のアプリに
合わせてあり、実際に存在しない機能や表示は載せない**（審査ガイドライン 2.3.3）。

- レイアウトの値は `ContentView` / `AppRowView` の padding・フォントサイズをそのまま
  写している。つまみ 18×14pt、トラック 4pt、行の高さ 60.5pt は macOS 26 の実機から測った
- 状態の決まり（並び順、コントロールが見える条件、メーターの長さ、ダッキング中の表示）
  は `shots.js` の先頭に書いた。状態を足すときは、アプリが実際にそう表示するかを確かめる
- 言語ごとに、その言語の Mac で実際に出る表示にする。AppMixer 自身の文言は
  `bundle/<言語>.lproj/Localizable.strings` と同じもの（`app.js` の `UI`）、
  アプリ名とデバイス名は macOS が返す名前（英語の Mac では「ミュージック」ではなく
  「Music」、「MacBook Air のスピーカー」ではなく「MacBook Air Speakers」）

アプリ側のレイアウトや文言を変えたら、`app.js` / `styles.css` も合わせて直すこと。

## ファイル

| ファイル | 役割 |
|---|---|
| `shots.js` | 1 枚ごとの画面の状態、背景のウインドウ、文言（日本語・英語） |
| `app.js` | 状態からポップオーバー・メニューバー・背景・文字組みを組み立てる |
| `styles.css` | 見た目（1440×900 で組み、2 倍で書き出す） |
| `index.html` | 版下。`?shot=<id>&lang=<ja\|en>` で 1 枚を選ぶ |
| `export_assets.swift` | SF Symbols とアプリアイコンを PNG に書き出す |
| `render.sh` | 部品を作り、Chrome のヘッドレスで全枚数を書き出す |

`build/` は生成物のため Git に入れない。他社アプリのアイコン（Chrome・Discord など）は
この Mac にインストールされているものから毎回取り出す。

必要なもの: Google Chrome、Swift（Xcode の Command Line Tools）、`shots.js` で
アイコンを使っているアプリ（Discord・Google Chrome・FaceTime・ミュージック）。

手元で確かめるときは、`render.sh` を一度実行して部品を作ってから `index.html` を
Chrome で開き、ウインドウを 1440×900 にする。

## App Store Connect へ差し替える

配信中のバージョンのスクリーンショットは変えられない。**次のバージョンで差し替える。**

1. App Store Connect で次のバージョン（例 1.0.2）を先に作る
2. そのバージョンの「App プレビューとスクリーンショット」→ Mac に、
   `build/ja` の 5 枚を日本語へ、`build/en` の 5 枚を英語（アメリカ）と英語（カナダ）へ入れる
3. あとは `docs/release-flow.md` のとおり `bundle/Info.plist` を同じバージョンに上げて
   `main` へマージする。CI（`scripts/asc.py submit`）は既存のバージョンを使うので、
   入れておいたスクリーンショットのまま審査に出る

先にバージョンを作らずにマージすると、CI が新しいバージョンを作って**前のスクリーン
ショットを引き継いだまま**すぐ審査に出してしまう。
